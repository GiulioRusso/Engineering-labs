Problem. A photo gallery holds hundreds of high-resolution images. Loading all of them at start-up wastes seconds and memory on pictures the user may never scroll to.

Solution. Give the gallery a stand-in, a proxy, with the same Image interface. It is cheap to create and remembers only the file name. On the first display() it creates the real image, then forwards that call and every later one to it.

  1. The proxy implements the same interface as the real object.
  2. It decides when (and whether) to create or reach the real object.
  3. Then it forwards the call.

Where you meet it

Lazy loading in ORMs, smart pointers (std::shared_ptr controls access and lifetime), remote proxies that send calls over a network (RPC stubs), access-control and caching proxies.

Common mistakes

Hiding a slow operation behind an innocent-looking call: the first display() takes much longer than the rest, which surprises the caller.
