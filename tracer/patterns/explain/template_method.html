Template Method

What you are looking at

Left: the real C++ program, the line being executed highlighted. Right: the objects alive at this step (name : class, then their fields), grey arrows for the references they hold, the orange arrow for the call or return happening now. Underneath, what the program has printed. Press play, or step with the play bar.

Problem. Exporting data as CSV or JSON follows the same steps: header, one line per row, footer. Copying that sequence into each exporter duplicates the skeleton, and the copies drift apart.

Solution. The base class writes the skeleton once in a non-virtual method, exportAll(), which calls virtual step methods. Subclasses override only the steps. Some steps have a default in the base class (a hook) that subclasses may override or not.

  1. The algorithm’s order lives in one base-class method.
  2. Steps are virtual: abstract where every subclass must decide, with a default (a hook) where it is optional.
  3. Subclasses never change the order, only the steps.

Where you meet it

Framework base classes (a test case’s setUp, test, tearDown), game loops (update, draw), parsers with overridable callbacks, std::streambuf overflow hooks.

Common mistakes

Letting subclasses override the template method itself, which breaks the guaranteed order, and long chains of inheritance where nobody can tell which step runs where. Strategy is the alternative based on composition.
