Problem. Some things should exist once in a program: one log file, one configuration, one connection pool. If every part of the code created its own, they would fight over the file and disagree about the settings. Passing one object around everywhere is tedious.

Solution. Make the constructor private, so nobody can write new Logger, and give the class a static function instance() that returns the one object, creating it on the first call. In modern C++ a function-local static does exactly that, and is thread-safe.

  1. Private constructor; copying deleted.
  2. static Logger& instance() holds a static Logger only; inside.
  3. Everyone calls Logger::instance() and gets a reference to the same object.

Where you meet it

Loggers, application settings, hardware drivers (one serial port), caches. Many frameworks offer the same idea as “a service registered once” in a dependency-injection container.

Common mistakes

Using singletons as hidden global variables: any code can reach them, so tests cannot replace them and dependencies become invisible. Prefer passing the object in, and keep Singleton for things that truly must be unique.
