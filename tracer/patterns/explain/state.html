Problem. A turnstile reacts to a coin and a push differently when locked and unlocked. A switch (state) inside every method spreads the rules of each state over many functions, and adding a state means editing all of them.

Solution. One class per state, all with the same methods (one per event). The turnstile keeps a pointer to its current state and forwards every event to it. A state object handles the event and, when needed, tells the turnstile to switch to another state object.

  1. A State interface with one method per event.
  2. One class per state holds only that state’s rules.
  3. The context forwards events and lets states replace its current state.

Where you meet it

Network connections (closed, listening, established), game characters (idle, running, jumping), order workflows (placed, paid, shipped), UI tools in a drawing program, any finite-state machine.

Common mistakes

States that need lots of data from the context, or transitions scattered so widely that the overall state diagram is no longer visible anywhere. Draw the diagram first.
