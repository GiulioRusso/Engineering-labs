Problem. A navigator estimates travel time differently for cars, walkers and cyclists. An if (mode == CAR) … else if … inside the navigator grows with every mode and mixes unrelated rules in one function.

Solution. Put each algorithm in its own class behind one interface, RouteStrategy. The navigator holds a pointer to a strategy and delegates the varying part to it. Switching mode means pointing at another object; the navigator’s code does not change.

  1. One interface for the family of algorithms.
  2. The context holds a strategy and calls it.
  3. Strategies can be swapped at run time.

Where you meet it

The comparator passed to std::sort, payment methods at a checkout, compression algorithms, the loss function of a neural network, routing modes in map apps.

Common mistakes

Creating strategy classes for a choice that never changes (a plain function would do), or leaking strategy-specific details into the context.
