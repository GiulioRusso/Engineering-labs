Problem. The climate app works with any TemperatureSensor that returns °C as a double. An old probe you cannot modify returns tenths of a degree Fahrenheit as an int. Changing the app for every odd device would spread conversions everywhere.

Solution. Write a small class that implements TemperatureSensor and holds the probe. Its celsius() calls the probe’s own method and converts the answer. The app talks to the adapter exactly as to a real sensor; the probe is untouched.

  1. Implement the interface the client expects.
  2. Keep a reference to the existing object (the adaptee).
  3. Translate each call: rename, reorder arguments, convert units.

Where you meet it

Wrapping a C library in a C++ class, connecting a third-party logger to your logging interface, std::stack adapting a std::deque, power plug adapters (the name comes from there).

Common mistakes

Putting business logic in the adapter; it should only translate. And adapting when you own both sides: then just change the interface.
