Problem. An HTTP request has a method, a URL, any number of headers and maybe a body. A constructor with all of them as parameters is unreadable and forces you to pass blanks; setting fields one by one leaves half-made objects around that might be used too early.

Solution. A separate builder collects the parts through small, named methods, each returning the builder so calls chain. Only build() creates the product, after checking that everything required is there. The product itself can then be immutable.

  1. Builder methods set one part each and return *this.
  2. build() validates, then creates the finished object.
  3. The product has no setters: once built, it cannot change.

Where you meet it

Request builders in HTTP libraries, StringBuilder, query builders for SQL, configuration objects in test code, Protocol Buffers message builders.

Common mistakes

Using a builder for a class with two fields (a constructor is clearer), or letting build() skip validation, which brings the half-made objects back.
