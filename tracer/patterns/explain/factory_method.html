Problem. A dialog box draws itself the same way on every platform, except for the buttons: Windows buttons and web buttons are different classes. If render() wrote new WinButton it would be tied to Windows forever.

Solution. The base class writes render() once and, where it needs a button, calls a virtual method createButton(), the factory method. Each subclass overrides only that method to create its kind of button. The shared code works with the Button interface and never names a concrete class.

  1. Products share an interface (Button).
  2. The creator’s general algorithm calls createButton().
  3. Each concrete creator overrides it to return its product.

Where you meet it

GUI toolkits creating platform widgets, document editors creating the right document type, test code overriding a factory to return fakes, C++ std::make_unique wrapped in a virtual function for plug-ins.

Common mistakes

Writing a big switch (platform) in the base class instead: every new platform means editing shared code. And creating a subclass just to change one product when a simple parameter would do.
