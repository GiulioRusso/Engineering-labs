Rotation matrices

What you are looking at

The world frame (thin) and a body frame x′ y′ z′ (thick, red–green–blue) attached to a small aircraft-like body, turning from the world frame to its final orientation as the clock runs. A vector p fixed in the body turns with it. The panel shows the rotation matrix R.

A robot has to know which way each link and the gripper are pointing. That orientation is a rotation from a reference frame, and it is stored as a 3×3 matrix with a very concrete meaning: its three columns are the unit vectors of the rotated frame, x′, y′ and z′, written in the reference frame’s coordinates. Multiplying R by a vector expressed in the body frame gives the same vector expressed in the world frame. The three simplest rotations are about a single axis; that axis stays put and the other two turn in its plane.

$$R_z(\vartheta) = \begin{bmatrix} \cos\vartheta & -\sin\vartheta & 0\\ \sin\vartheta & \cos\vartheta & 0\\ 0 & 0 & 1\end{bmatrix}, \qquad R^\mathsf{T}R = I, \quad \det R = 1, \qquad p^0 = R\,p^1$$
  1. Read the columns: where the body’s x, y and z axes point now.
  2. Orthonormal columns: the inverse is just the transpose, R⁻¹ = Rᵀ.
  3. The same R also rotates a vector: R p gives p turned with the body.

Worked example

R_z(90°) = [[0, −1, 0], [1, 0, 0], [0, 0, 1]]: first column (0, 1, 0), so x′ now points along the world y; second column (−1, 0, 0), y′ along −x; z′ unchanged.

Common mistake

Reading the rows instead of the columns. The rows are the world axes seen from the body frame (the columns of Rᵀ).

Try it

Set 90° about each axis in turn and check which column of the matrix stays (0, 0, 1), (0, 1, 0) or (1, 0, 0).

45° about x

x′ stays on the world x axis; y′ and z′ tip by 45° in the y–z plane, so the second and third columns contain ±0.71.

180° about y

y′ stays; x′ and z′ flip: R = diag(−1, 1, −1). A half turn is its own inverse.

Back again

R_z(−90°) is the transpose of R_z(90°): turning back is the inverse rotation.

Composing rotations

What you are looking at

Two rotations played one after the other: the faint frame is the orientation after the first, the thick one after both. The panel says which matrix product that is, and whether the other convention would end somewhere else.

Orientations are built from several simple rotations, and the order matters. If each rotation is about an axis of the current, already-moved frame (as when a joint turns about its own axis), the matrices multiply left to right: R = R₁R₂. If each is about a fixed world axis, the new rotation goes on the left: R = R₂R₁. Rotations about different axes do not commute, so the two answers differ. This is exactly how a robot arm stacks its joints: each joint rotates about an axis of the link before it.

$$\text{current frame: } R = R_1 R_2, \qquad \text{fixed frame: } R = R_2 R_1, \qquad R_1R_2 \ne R_2R_1 \text{ in general}$$
  1. Current axes: post-multiply, in the order the rotations are made.
  2. Fixed axes: pre-multiply, so the list reads backwards.
  3. Rotations about the same axis commute; their angles add.

Worked example

90° about z, then 90° about the new x: R = R_z R_x = [[0, 0, 1], [1, 0, 0], [0, 1, 0]]. The same two about fixed axes: R_x R_z = [[0, −1, 0], [0, 0, −1], [1, 0, 0]]: x′ ends along world y in the first case, along world z in the second.

Common mistake

Multiplying the matrices in the order the rotations are listed without asking about which frame each one is made.

Try it

Keep the angles and flip “current” to “fixed”: the final frame jumps, the intermediate one does not.

About fixed axes

The second 90° is about the world x axis, not the turned one: R = R_x R_z. A different orientation from the same two moves.

Swapped order

x first, then z: yet another result. Three-dimensional rotations do not commute.

Same axis

30° then 60° about z: 90° about z, in either order and either convention.

Euler angles and roll–pitch–yaw

What you are looking at

The three elementary rotations of the convention played in turn, each about the current frame; the two faint frames are the orientations after the first and second. The panel shows R and the three angles recovered from it.

Nine numbers with six constraints leave three degrees of freedom, so three angles are enough to describe any orientation. ZYZ Euler angles turn about z, then the new y, then the new z, and suit spherical wrists. Roll–pitch–yaw turns about z (yaw), then y (pitch), then x (roll), and suit vehicles and the end-effector of a robot. Every three-angle description has a weak spot: when the middle rotation lines up the first and third axes, the first and third angles do the same thing. One degree of freedom is lost, the angles cannot be recovered uniquely, and near it small orientation changes need huge angle changes. That is gimbal lock, and the reason quaternions exist.

$$R_{ZYZ} = R_z(\varphi)R_y(\vartheta)R_z(\psi), \qquad R_{RPY} = R_z(\varphi)R_y(\vartheta)R_x(\psi), \qquad \vartheta = \operatorname{atan2}\!\left(\sqrt{r_{13}^2 + r_{23}^2},\, r_{33}\right)$$
  1. Build R by multiplying the three elementary matrices left to right.
  2. Back from R: θ from the third column (ZYZ) or the third row (RPY), then φ and ψ with atan2.
  3. ZYZ is singular at θ = 0 or 180°; RPY at pitch ±90°.

Worked example

ZYZ with φ = 30°, θ = 45°, ψ = 60°: third column of R = (0.612, 0.354, 0.707), so θ = atan2(√(0.612² + 0.354²), 0.707) = 45°, and φ = atan2(0.354, 0.612) = 30°.

Common mistake

Averaging or interpolating Euler angles. Halfway between two orientations is not the orientation at half the angles, especially near a singularity.

Try it

In ZYZ set θ = 0 and move φ, then ψ: they turn the body about the same axis.

Gimbal lock (ZYZ)

θ = 0: the second rotation does nothing, so the first and third are both about z. Only φ + ψ = 90° can be recovered; the panel reports ψ = 0 by convention.

Roll–pitch–yaw

Yaw 30° about z, pitch 20° about the new y, roll 40° about the newest x: the way an aircraft’s attitude, or the Jaco2 end-effector’s orientation in the project (Rot2rpy), is written.

Pitch 90°

The nose points straight up: yaw and roll now turn about the same axis. Only φ − ψ is defined.

Axis–angle and unit quaternions

What you are looking at

The rotation axis r (orange) and the body turning about it from the start to the angle θ, the tip of x′ leaving a trail. The panel shows R, the unit quaternion and the orientation error from the start.

Euler’s rotation theorem: any orientation is reached by a single rotation by an angle θ about some axis r. A unit quaternion packs exactly that into four numbers: a scalar η = cos(θ/2) and a vector ε = sin(θ/2) r. Unlike three angles it has no singularity, interpolates smoothly (slerp), and gives a clean measure of how far one orientation is from another. The Jaco2 project controls the gripper’s orientation with the quaternion error e_O = η ε_d − η_d ε − ε_d × ε, which is zero when the two agree and behaves like sin of half the angle between them.

$$\mathcal Q = \{\eta, \boldsymbol\varepsilon\} = \left\{\cos\frac\vartheta2,\ \sin\frac\vartheta2\,\mathbf r\right\}, \qquad \eta^2 + \|\boldsymbol\varepsilon\|^2 = 1, \qquad e_O = \eta\,\boldsymbol\varepsilon_d - \eta_d\,\boldsymbol\varepsilon - \boldsymbol\varepsilon_d\times\boldsymbol\varepsilon$$
  1. Axis and angle → quaternion: half the angle.
  2. Q and −Q are the same orientation; QuatError flips the sign to take the shorter way.
  3. Quaternion → R and back without any singular case (Rot2Quat).

Worked example

θ = 120° about r = (0.81, 0.30, 0.50): η = cos 60° = 0.5, ε = sin 60° × r = (0.70, 0.26, 0.43). Error from the start: |e_O| = sin 60° = 0.866.

Common mistake

Forgetting the half angle: a quaternion with η = 0 is a 180° rotation, not 90°.

Try it

Play the clock and watch |e_O| grow as sin(θ/2): almost linear for small errors, which is why a proportional controller on e_O works well.

A small error

10°: |ε| = sin 5° = 0.087 ≈ θ/2 in radians. Close to the target, the quaternion error is just half the rotation vector.

Half a turn

180°: η = 0 and ε = r. The furthest any orientation can be from another.

Jaco2 task 3

The project rotates the gripper by 45° about its own z while tracing the square: Q = {cos 22.5°, (0, 0, sin 22.5°)} = {0.924, (0, 0, 0.383)}. The CLIK loop drives e_O to below 5·10⁻⁵.

Homogeneous transforms

What you are looking at

A frame 1 placed at origin o₁ (grey arrow) with orientation R (yaw only here), and a point given by its coordinates p¹ in frame 1: the orange arrow R p¹ from o₁ and the result p⁰ in world coordinates (blue).

Position and orientation together form a pose. A point known in frame 1 (say, the tip of a gripper in the gripper’s own frame) is found in the world frame by first rotating its coordinates and then adding where frame 1 is. A 4×4 homogeneous matrix packs both steps into one product, and chains of them simply multiply: frame 0 to 1 to 2 to the gripper. This is how a robot’s forward kinematics is computed, one link at a time.

$$\mathbf p^0 = \mathbf o_1^0 + R_1^0\,\mathbf p^1 \quad\Leftrightarrow\quad \begin{bmatrix}\mathbf p^0\\1\end{bmatrix} = \underbrace{\begin{bmatrix}R_1^0 & \mathbf o_1^0\\ \mathbf 0^\mathsf{T} & 1\end{bmatrix}}_{T_1^0}\begin{bmatrix}\mathbf p^1\\1\end{bmatrix}, \qquad T_2^0 = T_1^0\,T_2^1$$
  1. Rotate the coordinates: R p¹.
  2. Translate: add o₁.
  3. Inverse: T⁻¹ = [Rᵀ, −Rᵀo₁; 0, 1], not the plain matrix inverse of each block.

Worked example

Frame 1 at o₁ = (0.5, 0.4, 0.2), yawed 40°; p¹ = (0.6, 0.3, 0.4). R p¹ = (0.267, 0.616, 0.4), so p⁰ = (0.767, 1.015, 0.6).

Common mistake

Adding the translation before rotating. The offset o₁ is already in world coordinates; only p¹ needs rotating.

Try it

Change only the yaw: the orange arrow swings about o₁, and the blue one follows.

Translation only

R = I: p⁰ = o₁ + p¹, plain vector addition.

Rotation only

o₁ = 0 and a 90° yaw: p⁰ = R p¹ = (−0.3, 0.6, 0.4).
