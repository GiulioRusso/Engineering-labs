A channel code adds redundant bits so that the receiver can detect and correct errors made by the channel. A code's rate is the share of data bits among all bits sent; it trades against how many errors the code can fix.

The repetition code

What you are looking at

Left: 24 message bits, columns from left to right. The top row is what was sent (blue = 1, grey = 0), the middle rows are the n received copies with flips in red, and the bottom row is the majority vote, with wrong decisions shown as big red dots. Top right: bit error rate after the vote against n. Bottom right: error rate against rate 1/n, with the capacity C dashed. Below: the measured error rate of a long run.

Send each bit n times (n odd) and take the majority. The decision is wrong only if more than half of the copies flipped, which becomes very unlikely as n grows.

$$P_b=\sum_{j>n/2}\binom nj e^j(1-e)^{n-j},\qquad n=3:\ P_b=3e^2-2e^3$$

Worked example

e = 0.1, n = 3: P_b = 0.03 − 0.002 = 0.028, about 3.5 times fewer errors, at the cost of sending three times as many bits.

Common mistake

Concluding that reliability costs rate. Repetition drives the rate to zero, but Shannon proved that codes at any fixed rate below C can make errors as rare as you like. LDPC and turbo codes come close to that limit.

Try it

Set e = 0.3 and raise n: the errors still go away, but the point in the bottom chart slides towards rate 0.

No code

n = 1: every flip is an error and the error rate is e.

Seven copies

Four of seven must flip: about 0.3 % errors at e = 0.1, but only one data bit per seven channel uses.

The Hamming (7,4) code

What you are looking at

Left: the seven bits of a codeword placed in the regions of three circles. Each circle holds four bits and must contain an even number of 1s; a circle that does not is red. Top right: sent and received bits by position. Bottom right: the distance from the received word to each of the 16 codewords; the sent one is green, and the decoder picks the nearest. Below: block error rate with and without the code.

Four data bits get three parity bits, a rate of 4/7. Each parity bit makes its circle even. If one bit flips, exactly the circles containing it become odd, and every position is in a different set of circles, so the odd circles point to the culprit.

$$s=(s_4s_2s_1)_2=\text{position of the flipped bit},\qquad s_j=\bigoplus_{i\,:\,i\,\&\,j}r_i$$
  1. Position i belongs to the circle j if bit j is set in the binary form of i (5 = 101: circles 1 and 4).
  2. Parity bits sit at positions 1, 2 and 4, each in only its own circle.
  3. The receiver recomputes the three checks; read as a binary number they give the syndrome.
  4. Syndrome 0: accept. Otherwise flip the bit at that position.

Worked example

Data 1011 gives codeword 0110011. Flip position 5: checks 1 and 4 fail, check 2 passes, syndrome 101 = 5, corrected.

Common mistake

Trusting the decoder with two errors. Every pair of codewords differs in at least 3 places, so one error can be corrected, but two errors land nearer to a different codeword and get "corrected" into a third error.

Try it

Flip one data bit: the circles that contain it complain and point to it. Add a second flip: the decoder 'corrects' the wrong bit.

Flip d₂

Position 5 = 101: circles 1 and 4 turn red, circle 2 stays green. Only position 5 sits in exactly those two.

Flip p₄

A parity bit can be hit too: only circle 4 complains, and the data are untouched.

Two flips

Positions 3 and 6 flip: the syndrome is 3 ⊕ 6 = 5, so the decoder flips position 5 as well and outputs wrong data. A distance-3 code corrects one error, not two.
