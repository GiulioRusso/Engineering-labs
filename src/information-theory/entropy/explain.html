Information theory measures information in bits: how surprising a message is, how short it can be made, and how much of it a noisy channel can carry. Claude Shannon set it up in 1948, and every compressor, modem and phone still works within his limits.

Surprisal and entropy

What you are looking at

Left: the probability of each of five symbols (blue) and its surprisal log₂(1/p), scaled down by 8 (orange). Top right: the entropy of a coin as a function of its bias. Bottom right: a long random message from the source; the average surprisal of the symbols so far settles on the entropy (blue dashed). Below: each symbol's share of the entropy.

Learning that an event of probability p happened gives log₂(1/p) bits of information: a fair coin toss 1 bit, a 1-in-8 event 3 bits, a certain event 0 bits. The entropy is the average over the source: the information per symbol.

$$I(x)=\log_2\frac1{p(x)},\qquad H=\sum_x p(x)\log_2\frac1{p(x)}\ \text{bits},\qquad 0\le H\le\log_2 N$$
  1. Equal probabilities give the most entropy, log₂ N.
  2. A source that almost always sends the same symbol has entropy near 0.
  3. H is the smallest average number of bits per symbol any lossless code can reach (the source coding theorem).

Worked example

Weights 4, 2, 2, 1, 1 give p = 0.4, 0.2, 0.2, 0.1, 0.1. H = 0.4·1.32 + 2·0.2·2.32 + 2·0.1·3.32 = 0.53 + 0.93 + 0.66 = 2.12 bits, compared with 2.32 for five equal symbols.

Common mistake

Thinking of information as meaning. Entropy measures only unpredictability: a page of random letters has more of it than a page of English.

Try it

Drag one weight up to 10: the entropy falls towards 0, and rare symbols get larger surprisals.

All equal

No symbol is more predictable than another: H = log₂ 5 ≈ 2.32 bits, the most five symbols can carry.

Almost certain

A is sent 96 % of the time: H ≈ 0.3 bits. Each rare symbol is very surprising, but rare.

A biased coin

P(heads) = 0.1: H₂ = 0.47 bits. A thousand such tosses could be compressed into about 470 bits.

The Huffman code

What you are looking at

Left: the code tree built merge by merge. Each merge joins the two least likely nodes; the left branch is 0 (blue), the right is 1 (orange). Reading from the top down to a leaf gives its codeword. Top right: codeword lengths against the ideal log₂(1/p). Bottom right: entropy, Huffman average length, and a fixed 3-bit code. Below: bits used to send a random message.

Give short codewords to frequent symbols and long ones to rare symbols. Huffman's algorithm does this optimally: no prefix-free code has a smaller average length.

  1. List the symbols with their probabilities.
  2. Join the two least likely into a node whose probability is their sum.
  3. Repeat until one node is left: the root.
  4. Label the branches 0 and 1; each symbol's codeword is the path from the root.
$$H\le L=\sum_x p(x)\,\ell(x)

Worked example

p = 0.4, 0.2, 0.2, 0.1, 0.1: lengths 2, 2, 2, 3, 3 (1, 3, 3, 3, 3 is just as good). L = 2·0.8 + 3·0.2 = 2.2 bits against H = 2.12; a fixed-length code needs 3 bits.

Common mistake

Expecting L = H. Codeword lengths are whole numbers, so L meets H only when every probability is a power of ½. Coding blocks of symbols (or arithmetic coding) closes the gap.

Try it

Make one symbol much more likely: it gets the shortest code word and the average length falls toward the entropy.

Powers of ½

p = ½, ¼, ⅛, 1/16, 1/16: lengths 1, 2, 3, 4, 4 equal log₂(1/p) exactly, so L = H = 1.875 bits.

Nearly uniform

With nothing to exploit the code uses lengths 2 and 3, about 2.3 bits: not much better than 3-bit words.

The binary symmetric channel

What you are looking at

Left: the channel. Each bit arrives intact with probability 1 − e (green) or flipped with probability e (red); line thickness follows probability, and the input and output probabilities are written beside each node. Top right: the information that gets through per use, against the input probability. Bottom right: the capacity against e.

The output Y tells us something about the input X, but not everything. The mutual information is the uncertainty about Y minus the part due only to noise. Its maximum over all inputs is the channel capacity.

$$I(X;Y)=H(Y)-H(Y\mid X)=H_2\big(q(1-e)+(1-q)e\big)-H_2(e),\qquad C=1-H_2(e)$$

Worked example

e = 0.11: H₂(0.11) ≈ 0.5, so C ≈ 0.5. Half of every bit sent is lost to noise; at best one data bit gets through every two channel uses.

Common mistake

Thinking capacity is "1 − e". With e = 0.11 the channel delivers 89 % of bits correctly, but you do not know which ones; that uncertainty costs H₂(e) bits per use.

Try it

Raise the flip probability to 0.5: the capacity falls to zero. Move the input probability away from ½ and the mutual information drops below capacity.

e = ½

The output is a fair coin regardless of the input: H(Y) = H(Y|X) = 1, and nothing gets through.

Unequal inputs

Sending mostly zeros lowers H(Y) while the noise H(Y|X) stays the same: less information per use. For this channel, equal inputs are best.
